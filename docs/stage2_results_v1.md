### 3.2 진단: 정답 신호를 넣으면 흐름 판정은 10/10

흐름 판정 v1 규칙을 바꾸지 않고, 행위 감지 결과 대신 **최종 라벨의 신호**를 넣어 같은 사례를 다시 계산했습니다 (진단용, 규칙 변경 없음, `securityapp.eval.OracleFlowKt`로 재현).

| | 송금 전 경고 |
|---|---|
| 엔진 (행위 감지 결과 사용) | 3/10 |
| 흐름 판정에 정답 신호 사용 | **10/10** (9건은 첫 금전 권유 메시지에서, 1건은 마감 메시지에서) |

**흐름 판정 규칙 자체는 사기 흐름을 잡을 수 있습니다.** 놓친 원인은 그 앞 단계, 즉 신호를 찾지 못한 데 있습니다. 행위 단독이 9/10을 잡은 것도 같은 이야기입니다. 신호 하나는 대체로 찾지만, 흐름 판정이 요구하는 "요구 + 다른 분류 + 돈 요구" 조합이 갖춰질 만큼 찾지는 못합니다.

### 3.3 재현율이 낮은 까닭 (추정)
1. **평가 사례에서 기억한 표현을 일부러 뺐습니다** (docs/dev/02_act_rules_v0.md 3.1). 평가 세트를 규칙에 새지 않게 하려는 장치였고, 그 비용이 그대로 드러났습니다.
2. **개발 세트와 평가 세트의 문체가 다릅니다.** 개발 세트는 모델이 쓴 합성 대화입니다. 평가 세트는 기사·수사기관 자료의 인용과 서술을 뼈대로 재구성했습니다. 낱말 규칙(A안)은 표현이 바뀌면 놓친다는 약점(plan.md 4.3)이 그대로 나왔습니다.
3. 개발 세트에서는 사기 15/21을 경고했으므로 **개발 세트 성능이 평가 성능을 과대평가했습니다.** 개발 세트 33건으로는 표현의 폭이 부족했습니다.

## 4. 의미 검증 기준(plan.md 7.2)과 비교

| 기준 | 결과 | 판단 |
|---|---|---|
| 1. 기준선보다 확실히 나은가 | 오탐 14% → **0%**, 송금 전 경고 7/10 → **3/10** | **미달로 봄.** 오탐은 뚜렷하게 낮지만 놓치는 사례가 크게 늘어 "나은 방법"이라 할 수 없음 |
| 1. 행위+흐름이 행위 단독보다 나은가 | 오탐 33% → 0%, 송금 전 9/10 → 3/10 | 오탐을 없애는 효과는 분명함(흐름 판정 유지 근거). 재현율 손실은 3.2에 따라 행위 감지 쪽 원인 |
| 2. 오탐률 10% 이하 | 0/43 | **통과** |
| 2. 송금 전 경고율 70% 이상 | 3/10 | **미달** |
| 2. 상대 메시지만 볼 때 | "나 포함"과 같음 | 통과 |
| 3. 대상자 반응 | 아직 하지 않음 | — |

- 기준 1은 오탐만 보면 통과입니다. 하지만 송금 전 경고가 기준선보다 4건 적어서 통과로 적지 않았습니다.
- 7.2의 다음 행동 표를 그대로 적용하면 아래와 같습니다.
  - "2만 미달"이면 작업 4단계(엔진 개선)를 먼저 합니다.
  - "1 미달"이면 범위를 줄이거나 주제를 재검토합니다.
- 다만 3.2의 진단은 **흐름 판정 설계 자체는 유효하고, 부족한 것은 행위 감지의 재현율**임을 보여 줍니다. 그래서 1 미달의 "더 단순한 방식으로 축소"보다는 **작업 4단계(행위 감지 개선)**가 맞는 다음 행동이라고 봅니다. 결정은 사용자가 합니다 (결정 24로 기록 예정).

## 5. 작업 4단계 후보 (평가 세트를 새지 않게 하는 방법 포함)

| 후보 | 내용 | 평가 세트와의 거리 |
|---|---|---|
| ① 개발 세트 넓히기 | 문체가 다른 개발 대화를 더 모음. 다른 출처의 공개 사례(평가 10건과 다른 기사·자료)를 같은 방식으로 재구성하거나, 합성 대화를 더 다양한 지시로 받음 | 평가 사례를 보지 않고 규칙을 고칠 근거가 생김 |
| ② 소형 모델 (B안, plan.md 4.3) | 넓힌 개발 세트로 신호 분류 모델을 학습하고 규칙과 비교 | 표현 변화에 강함. 학습 데이터가 ①에 달려 있음 |
| ③ 흐름 조건 완화 | 낮은 재현율을 전제로 조합 조건을 줄임 (예: 돈 요구 + 다른 신호 1개) | 개발 세트와 AI-Hub 200건으로 오탐을 확인해야 함 |

- 어느 쪽이든 고친 엔진은 **v1.1 "평가 후 수정"**으로 보고하고, v1 결과는 지우지 않습니다.
- 같은 평가 세트를 다시 쓰면 규칙 작성자가 이 결과를 본 영향이 남습니다. 그래서 가능하면 **새로 재구성한 사기 사례 몇 건(새 평가 세트)**으로도 따로 확인합니다.

## 6. 기록해 둘 한계
- 사기 10건이라 한 건이 10%p입니다. 비율은 항상 건수와 같이 봅니다.
- 평가 사기 대화는 실제 대화가 아니라 공개 자료로 재구성한 것입니다. 실제 대화의 표현과는 또 다를 수 있습니다.
- 신호 체계는 평가 사례의 자유 메모에서 나왔습니다(02_act_rules_v0.md 3.3). 그래서 3.2의 10/10은 "신호 체계가 이 사례들을 설명한다"는 뜻이지, 다른 사례에도 통한다는 증거는 아닙니다.
