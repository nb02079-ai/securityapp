## 2. 무엇이 문제였나

### 2.1 행위 감지 재현율이 개발 세트보다 크게 낮음
- 개발 세트에서는 v1.1에서 38/61까지 올랐지만, 처음 보는 문장에서는 대부분의 신호를 놓쳤습니다.
- 재현율: R2 0.08, P1 0.14, P2 0.13, D2 0.29, D1 0, D5 0, G3 0.
- 정밀도는 대체로 높습니다 (D2 1.00, P1 1.00, D4 1.00). 즉 v1.1 규칙은 **개발 세트의 표현에 맞춰졌고 일반화가 약합니다**.
- 예: "보증금이랑 임대료만 입금하면", "투자금에 비례해서 수익을 나눠줘요" 같은 재구성 문장이 사전에 없는 표현이었습니다.

### 2.2 방 단위 판정이 흩어진 신호를 못 모음
- 흐름 판정은 방마다 따로 셉니다. 신호가 단체방과 1:1 방에 나뉘어 나오면 어느 방도 3종류를 채우지 못합니다.
  - C02: 단체방에서 P3·P1·R1, 1:1 방에서 D2·D4·D7. D4는 종류 수에 넣지 않으므로 1:1 방은 2종류에 그쳤습니다.
  - C01도 비슷합니다. 단체방의 R1·G2와 1:1 방의 D7·G2가 나뉘어 주의에 그쳤습니다.
- 정답 신호로 돌렸을 때 놓친 3건(C02, C07, C08) 가운데 C02가 이 경우입니다.
- 나머지 두 건은 경고할 시간이 거의 없는 짧은 사례입니다.
  - C07: 첫 송금 직전이 3번입니다.
  - C08: 상대 메시지가 6개뿐이고 D3·D7·D6만 나옵니다.

### 2.3 통화 메시지
- C04·C07은 핵심 권유 일부가 전화(`voice`) 안에 있습니다. 앱이 볼 수 없는 부분이므로 이 손실은 제품의 한계로 받아들입니다 (결정 26).

### 2.4 행위 단독이 높은 이유
- 행위 단독은 신호 하나만 나와도 경고합니다. 그래서 홀드아웃 재현율은 8/10입니다.
- 대신 일반 대화 오탐이 큽니다: 기존 평가 세트 14/43(33%, v1), 개발 세트 일반 대화 228건에서 82/228(36%, v1.1).

## 3. plan.md 7.2 기준과 비교

| 기준 | 결과 | 판단 |

| 1. 기준선보다 확실히 나은가 | 행위 + 흐름 2/10은 기준선 6/10보다 낮음. 오탐은 기존 세트에서 0/43 vs 기준선 6/43 | 오탐은 낫고 재현율은 못함 → **미달** |

| 2. 일반 대화 오탐 10% 이하 | 행위 + 흐름 경고 0/43(기존 세트, v1), 경고 0/228·주의 5/228(개발 세트, v1.1) | 통과 (v1.1의 평가 세트 오탐은 아직 안 잼) |

정리하면 "오탐을 거의 내지 않는 대신 대부분 놓친다"입니다. 개발 세트에서 올린 재현율은 새 문장으로 옮겨 가지 않았습니다. 규칙을 손으로 늘리는 방식(A안)의 한계가 숫자로 확인된 셈입니다.
