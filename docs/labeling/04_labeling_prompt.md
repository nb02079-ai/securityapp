## 준비

가림판과 시트는 **번호를 섞은 판**(시드 `20261021`)으로 만듭니다. 섞은 가림판은 기록용으로 `docs/labeling/blind_cases_seed20261021.md`에 둡니다 (자유 메모 때의 `blind_cases.md`와 번호가 다름).

```
python tools/scam/make_blind.py       data/eval/scam/*.jsonl --out "<저장소 밖>/label_in"  --shuffle-seed 20261021
python tools/scam/make_label_sheet.py data/eval/scam/*.jsonl --out "<저장소 밖>/label_all" --shuffle-seed 20261021
python tools/scam/make_label_xlsx.py  data/eval/scam/*.jsonl --out "<저장소 밖>/label_me.xlsx" --shuffle-seed 20261021 --cases C03,C05,C06,C08,C09
```

### 사용자 5건을 고른 기준
- 자유 메모에서 "첫 이상 신호"가 세 모델 모두 달랐던 사례 (필수, plan.md 5.2)
- "첫 금전 요구"가 권유냐 구체 지시냐로 갈린 사례 2건
- 방이 여러 개인 가장 긴 사례
- 송금이 끝까지 없는 사례 (첫 송금 직전 규칙 4번 시험)

## 모델 라벨러 진행 방법
1. 모델마다 **새 대화**를 엽니다. Claude는 **이 프로젝트 밖에서** 엽니다 (프로젝트 문서·기억에 있는 분석 결과가 섞이지 않게).
2. 아래 지시문을 붙여 넣고 `blind_cases_seed20261021.md`, `03_label_guide.md`, `label_messages.csv`, `label_points.csv`를 첨부합니다. `blind_key.csv`는 넣지 않습니다.
3. 결과는 `labels_<모델>_messages.csv`, `labels_<모델>_points.csv`로 저장합니다 (예: `labels_grok_messages.csv`).
4. 받은 뒤 확인: messages 122줄·points 10줄(제목 줄 제외), 신호 칸에 기준표 코드만 있는지.
   - 중간에 끊기면 "C06부터 이어서 채워 주세요"라고 요청합니다.
   - CSV 파일로 못 돌려주면 표나 텍스트로 받아도 됩니다 (변환은 원래 세션에서).

```
첨부한 대화 기록 파일(이름이 blind_cases로 시작하는 .md)에는 10개의 대화 기록(C01~C10)이 있습니다. 모두 실제 금융 사기 사례를 바탕으로 재구성한 것이고, "나"가 피해자입니다.
첨부한 03_label_guide.md(라벨 기준표)에 따라 라벨을 붙여 주세요.

[규칙]
- 기준표의 정의와 "붙이지 않는 경우"를 그대로 따르세요. 기준표에 없는 신호 코드를 만들지 마세요.
- 웹 검색을 하거나 원래 기사·사건을 추측해서 찾지 마세요. 표에 보이는 것만 보세요.
- 상대방 메시지 하나도 빠뜨리지 마세요. 신호가 없는 메시지는 signals 칸을 비우되 stage와 confidence는 채우세요.
- 확신이 없으면 confidence를 "낮음"으로 하고 note에 고민한 다른 신호를 적으세요.
- 금전 지점 세 개(기준표 4장)를 모두 채우세요. "보냈어요"가 돈인지, "해 볼게요"가 의사 표현인지 송금인지 반드시 구분하세요.

[출력]
첨부한 label_messages.csv와 label_points.csv의 빈 칸을 채워 같은 이름의 CSV 파일 두 개로 돌려주세요.
- 줄을 추가하거나 지우지 말고, case·seq·room·sender·text 칸은 바꾸지 마세요.
- 모든 사례를 끝낸 뒤, 기준표로 판단하기 어려웠던 점을 5줄 이내로 따로 적어 주세요.
```

## 사용자 진행 방법
1. `label_me.xlsx` 하나만 엽니다. 대화 전체("나"의 메시지는 회색), 코드표, 안내가 모두 들어 있습니다.
2. 노란 칸만 채웁니다: 신호는 칸을 눌러 ●를 고르고, 단계·확신은 드롭다운, 메모만 직접 입력. 오른쪽 "확인" 칸에 빠진 곳이 표시됩니다.
3. 사례마다 "금전 지점" 시트에서 세 지점을 번호 드롭다운으로 고릅니다.
4. 원래 사례 파일(`data/eval/scam/*.md`)·분석 문서·모델 라벨 결과는 **라벨링을 마칠 때까지 열지 않습니다.**
5. .xlsx 그대로 원래 세션에 가져옵니다.

**한계로 기록할 것**
- 사용자는 사례 작성 세션과 대화하며 자유 메모 분석을 읽었고, 2차에서는 1차 모델 결과와 갈린 곳 분석([05_label_agreement.md](05_label_agreement.md))까지 읽었습니다. 따라서 2차의 사람 라벨은 **독립 라벨이 아니며**, 사람–모델 일치율을 보고할 때 이 점을 함께 적습니다.
- 독립된 사람 라벨이 필요하면, 이 저장소와 분석을 보지 않은 지인 한 명에게 같은 엑셀 양식(5건)을 맡기는 것이 가장 깨끗합니다.

## 결과를 받은 뒤
- 계산: `tools/scam/agreement.py` (모델 3개 + 사람). 신호별 κ, 단계 κ, 금전 지점 세 개(완전 일치 / ±1)
- 갈린 메시지는 라벨러들의 메모를 보고 기준표 문구를 고칠지 정한다. **기준표를 고치면 고친 내용과 이유를 기록하고, 이미 붙인 라벨을 고쳐 쓰지 않고 새 회차로 다시 붙인다.**
- 최종 라벨
  - 신호·단계: 세 모델 다수결 (3명 중 2명 이상)
  - 셋이 모두 다른 칸, 금전 지점 세 개: 사용자가 기준표로 결정
  - **사례를 쓴 세션은 최종 라벨을 정하지 않는다** (plan.md 5.2 "라벨은 작성자가 아닌 사람이")
- 회차별 일치율을 모두 남긴다. 기준표 수정 전후의 비교가 곧 기준표 검증 기록이다.
