# 2차 라벨링(기준표 v2): 모델이 적은 "판단이 어려웠던 점"

각 모델의 2차 대화 마지막 답변을 사용자가 그대로 옮겨 온 것입니다 (2026-10-22). 사례 번호는 시드 20261021 가림판 번호입니다.

## Grok
- 본인 증권계좌 안 매수 안내(C04·C08 단타)는 D2·first_suggest에는 포함되지만 송금(transfer)에는 제외하는 구분이 가장 까다로웠습니다.
- 송금 의사만 있고 실제 "보냈어요/입금했어요" 기록이 없는 경우(C06) first_transfer_before를 "금액만 있는 첫 지시"로 두는 규칙 적용이 애매했습니다.
- "보냈어요"가 이메일·캡처인지 실제 금전 송금인지(C03) 반드시 문맥으로 구분해야 했습니다.
- G2(화제 급전환) 시점과 R1(회원 맞장구) vs G1(상대가 "나"에게 준 것) 경계, D2/D3/D5 구분에서 확신이 낮은 경우가 있었습니다.
- 단체방 회원 메시지의 stage를 "신뢰"로 둘지, 운영자 메시지와 동일하게 돈 흐름 기준으로 둘지 판단이 필요했습니다.

## ChatGPT
1. 송금과 의사 표현의 구분: 이메일·사진 전송은 금전 송금으로 보지 않았고, "해 볼게요"는 실제 송금으로 처리하지 않았습니다.
2. 첫 송금 의사 직전: 명시적인 의사 표현이 없는 경우 기준표의 규칙에 따라 실제 송금 직전 메시지를 기준으로 판단했습니다.
3. 주식 매수와 송금의 구분: 본인 증권계좌 안의 상장 종목 매매와 상대가 판매하는 비상장주식 매수를 구분했습니다.
4. 신호 간 경계: 투자 권유와 대납 요구, 수익 보장과 실제 보상, 채널 이동과 단순 링크 안내가 겹칠 수 있는 경우 메모와 확신 수준에 반영했습니다.
5. 단계 판정: 첫 송금 이후의 메시지는 모두 추가요구로 처리하지 않고, 실제 내용이 신뢰 형성인지 출금 조건부 추가 입금인지 구분했습니다.

(참고: 사용자가 처음 올린 ChatGPT 파일은 1차 파일과 같은 것이어서 다시 받았고, 위 내용은 다시 받은 2차 대화의 것입니다.)

## Claude
- 송금이 없는 사례에서 4.3의 4번 규칙대로 "첫 구체 지시"를 적으면 C06은 송금 지점(11)이 의사 지점(17)보다 앞에 옵니다. "권유 ≤ 의사 ≤ 송금" 순서가 뒤집힙니다.
1. "각 방의 첫 메시지 = 접근" 규칙과 "첫 송금 뒤 요구 = 추가요구" 규칙이 부딪힙니다(C08-36). 저는 추가요구로 두었습니다.
2. 금액·보낼 곳 없이 "보내 주세요"라고만 한 직후 송금한 경우(C01-7, C07-7)가 정의상 '유도'가 됩니다. 돈도 정보도 아닌 심부름(C03-10)은 맞는 단계가 없어 '분류불가'로 두었습니다.
3. C02-9 "넣어 봤어요"가 상대가 정한 곳에 충전한 것인지, 본인 거래소 계좌에 넣은 것인지 글자만으로는 구분되지 않습니다.
4. 경계가 불분명한 신호가 있습니다. G4가 돈이 아닌 요청(C02-3 대화 붙잡기)에도 적용되는지, R1의 "단순 인사"와 출석 응답(C08-3·4)의 경계, D7 목록에 없는 정보(C04-8 손실 금액)를 어떻게 볼지가 정해져 있지 않습니다.
