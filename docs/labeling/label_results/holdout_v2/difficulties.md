# 홀드아웃(평가 세트 v2) 라벨링: 모델이 적은 "판단이 어려웠던 점"

각 모델의 답변을 사용자가 그대로 옮겨 온 것입니다 (2026-10-27). 사례 번호는 시드 20261027 가림판 번호입니다. 기준표는 v2.2입니다.

## ChatGPT
1. 간접적인 금전 요청: 수리비가 필요하다는 표현처럼 직접 송금을 요구하지 않은 메시지를 어디까지 금전 권유로 볼지 모호했습니다.
2. 투자 권유의 시작점: 추천 종목이나 투자 채널 소개가 실제로 돈을 쓰라는 권유인지, 단순한 정보 제공인지 구분이 어려운 경우가 있었습니다.
3. 송금 시점: 피해자의 계약·가입·수익 언급만으로 실제 송금 시점을 특정하기 어려워, 후속 메시지와 기준표의 간접 확인 규칙을 활용했습니다.
4. 단계와 신호의 중첩: 친밀감 표현과 금전 요구가 함께 나타나거나, 거절 뒤 붙잡는 메시지에서 R2와 G4를 함께 붙일지 판단이 필요한 경우가 있었습니다.
5. 추가 요구와 선납 구분: 투자 대행 수수료가 출금을 위한 선납인지, 최초 투자 비용인지 문면만으로 확정하기 어려운 경우에는 메모에 불확실성을 남겼습니다.

## Grok
- C02처럼 "나"가 명시적 송금 의사("보낼게요")를 밝히지 않고 바로 인출된 경우, 의사 지점과 송금 직전 지점을 어떻게 잡을지 애매했습니다 (가이드 4.2·4.3의 "의사 없이 바로 송금" 규칙을 적용해 동일 처리).
- C04·C05의 "구매/적금 넣기"가 계좌 밖 송금인지, 본인 계좌 내 매매인지 구분하는 데 가이드 4.3 정의를 엄격히 따랐습니다 (구매·입금은 송금으로 봄).
- 단체방 팀원 메시지(R1)와 운영자 메시지를 단계상 "신뢰"로 통일하는 규칙이 돈 흐름과 어긋나 보일 때가 있었습니다.
- G2(화제 급전환)는 한 메시지에만 붙이도록 되어 있어, 연속된 전환(연애→부업→적금)에서 어느 쪽에 붙일지 고민했습니다.
- "위약금·재주문·세금"처럼 출금 조건 추가 입금(D5)과 단순 추가 요구(D2)의 경계가 일부 사례에서 모호했습니다.

## Gemini
1. 메신저 외 수단(전화·앱 설치)의 송금 간접 증명: C02, C05 사례처럼 직접 계좌 이체 메시지 없이 앱 설치 후 통장 출금되거나 외부 쇼핑몰 결제로 이루어지는 경우, '첫 송금 직전' 상대 메시지 번호를 확정하기 어려웠습니다.
2. G3/G4 비교 대상 명시 기준: 거절이나 송금 반복 흐름이 여러 번 이어질 때 어느 번호를 기준점(비교 대상)으로 삼아 note에 적어야 하는지 경계가 다소 애매했습니다.
3. P1(수익 보장) vs R1(다른 회원 인증)의 구별: 단체방에서 바람잡이(회원)들의 수익 인증 메시지(R1)와 운영자의 수익 장담(P1)이 섞여 있을 때 맥락 구분이 미세한 부분이 있었습니다.
4. D3(선납/대납)와 D2(투자)의 중복 영역: 구매대행 리뷰 알바나 VIP 팬카드 발급 등 명목상 투자와 대납/수수료 성격이 동시에 나타나는 경우 라벨 선택에 고민이 되었습니다.

## 받은 파일 처리 기록
- Gemini는 CSV 대신 같은 내용의 .md로 돌려주었고, text 칸의 쉼표를 지운 줄이 16개 있었습니다. 줄 수와 case·seq는 시트와 같아서, text·room·sender 칸만 시트 값으로 되돌렸습니다 (라벨 칸은 그대로). points 파일에는 n_messages 칸이 없어 ChatGPT 파일의 값을 넣었습니다.
- 금전 지점에 "나"의 메시지 번호를 적은 칸이 2개 있었습니다: Gemini C07 first_intent_before=8, Grok C04 first_intent_before=10. 둘 다 모델끼리 갈린 칸이라 판정 양식에 들어가며, 판정 드롭다운에는 상대방 메시지 번호만 있습니다.
