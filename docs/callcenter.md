# 금융 콜센터 데이터 기록 (결정 28)

## 1. 출처
- AI-Hub「민원(콜센터) 질의-응답 데이터」에서 **금융/보험 라벨링데이터만** 씁니다. 원천데이터와 다른 도메인은 받지 않습니다.
- 조건: AI-Hub 약관상 제3자 제공·재배포가 금지됩니다. 원문은 저장소 밖에 두고, 저장소에는 ID와 숫자만 올립니다.
- 구조 확인(2026-10-27): Validation「상품 가입 및 해지」파일 하나를 봤습니다.
  - 문장 하나가 객체 하나인 JSON 목록입니다. 문장 10,912개가 대화 556개(`대화셋일련번호`)로 묶여 있습니다.
  - 대화 길이는 2~40문장이고 중앙값은 20문장입니다. 고객과 상담사가 번갈아 말하는 여러 턴 대화입니다.
  - 이체·송금·계좌·대출·출금·입금이 나오는 대화가 153개(28%)였습니다. 돈 이야기가 나오는 진짜 정상 대화라 오탐 측정에 맞습니다.

## 2. 변환 (`tools/aihub/import_callcenter.py`)
- 메시지 하나는 문장 하나입니다. 글은 네 칸(고객질문·상담사질문·고객답변·상담사답변) 가운데 비어 있지 않은 칸에서 가져옵니다.
- 메시지가 2개 미만인 대화는 뺍니다.
- "나"는 정하지 않습니다. 평가기가 고객과 상담사를 한 번씩 "나"로 놓고 돌립니다(결정 23).
- 나누기:
  - AI-Hub **Validation → 평가(봉인)**
  - Training → 시드 20261027로 섞어 85% 학습 / 15% 개발
  - AI-Hub가 이미 나눠 둔 것을 따르므로, 평가용 대화를 고르는 단계가 없습니다.

## 3. 주의: 말투 차이
- 이 데이터는 사람이 직접 친 글입니다(맞춤법·문장부호 정돈, `OO`·`000` 가림). KorCCVi는 음성 전사입니다.
- 그래서 모델이 "전사 말투 = 사기, 정돈된 글 = 정상"으로 배울 수 있습니다. 이렇게 되면 이 데이터에서의 오탐은 실제보다 낮게 나옵니다.
- 대응:
  - 모델 입력을 정규화합니다. 문장부호와 띄어쓰기를 정리하고, 가림 기호를 하나로 통일합니다.
  - 오탐은 출처별로 따로 보고합니다(KorCCVi 일반 통화 / 콜센터). KorCCVi 일반 통화 쪽 오탐이 더 정직한 숫자입니다.
