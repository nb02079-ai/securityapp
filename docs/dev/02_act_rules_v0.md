# 행위 감지 규칙 v0 (작업 2-3 1차)

- 날짜: 2026-10-23
- 코드: `engine/src/main/kotlin/securityapp/engine/` — `normalize/`(정규화·금액), `acts/`(행위 감지)
- 상태: **기준표 정의와 기준표 예시만으로 만든 첫 판.** 개발 세트(2-2)가 오면 그것만 보고 다듬는다. 평가 세트로는 아직 한 번도 돌리지 않았다.

## 1. 만든 것

| 부분 | 내용 |
|---|---|
| 정규화 | 소문자·NFC, 보이지 않는 문자 제거, 글자 사이 공백·기호 제거("입 금", "대.출", "비*밀" → 이어 붙임). 근거 구간을 원래 문장 위치로 되돌림 |
| 금액 | "300만 원", "1억 5천만", "5,000원", "오십만" → 원 단위 숫자. 주식 수량·퍼센트는 제외 |
| 행위 감지 | 신호 17개. 대부분 메시지 하나만 보고, R1(단체방·운영자 여부)·G2(앞서 돈 이야기가 있었는지)·G3(앞선 요구 금액)·G4("나"의 거절)는 방 맥락을 봄 |
| 방 맥락 | 메시지 원문은 저장하지 않고 보낸 사람 수, 돈 이야기 시작 여부, 최대 요구 금액, 직전 "나"의 거절 여부만 남김 |
| 기준표 규칙 반영 | 매도 안내만은 D2 아님, 출금용이면 D3 대신 D5, 금액만 묻는 건 D7 아님, 약속은 G1 아님, 가능성만은 P1 아님, 단체방 운영자 메시지는 R1 아님, "나"의 메시지에는 신호 없음 |

## 3. 평가 세트와의 거리 두기

### 3.1 일부러 넣지 않은 표현
작성자(이 세션)는 평가 사례를 읽은 적이 있습니다. 처음 쓴 표현 목록을 다시 보니 평가 사례에서 본 표현이 섞여 있어 **모두 뺐습니다.** 이 때문에 평가 세트에서 놓치는 메시지가 생길 수 있지만, 그것이 정직한 결과입니다.

| 뺀 표현의 종류 | 예 (평가 사례에서 기억한 것) |
|---|---|
| 특정 일상 표현 | 출근 이야기, 특정 인사말 |
| 특정 권위 근거 | 팬 언급, "검색해 보시면" |
| 특정 핑계 | 일정이 생겨 못 간다는 말, 통화가 끊긴다는 말 |
| 특정 금액 규칙 | 분배 비율, "공격적으로", 규모 키우기 |
| 특정 붙잡는 말 | "멈추지 말라", 증명 요구 |
| 특정 출금 방해 | "채우지 않으면" |
| 특정 직업 | 평가 사례에 나온 직업 이름 (대신 "~에서 일하고 있다" 같은 일반 모양과 기준표 예시의 직업만) |
| 특정 경로 | 평가 사례에 나온 송금 방법 이름 (기준표의 ATM·창구만) |

### 3.2 겹침 검사 (`tools/scam/check_lexicon_leak.py --min 4`)
표현 조각 98개 중 평가 문장에 그대로 들어 있는 4자 이상 조각은 14개였고, 모두 **일반 낱말**로 판단했습니다: 감사합니다, 계좌번호, 그만하고, 돌려받으, 돌려줄게, 보내드렸, 보내드릴, 영상통화, 전화번호, 주민등록, 지갑주소, 텔레그램, 해드렸습, 휴대전화번호. 이 중 6개는 기준표에도 있는 낱말입니다. 평가 문장의 구절(5자 이상의 특정 표현)을 옮긴 것은 없습니다.

### 3.3 남는 한계
- **신호 체계 자체가 평가 사례에서 나왔습니다.** 17개 신호는 평가 사례 10건의 자유 메모(작업 1단계)를 보고 정했습니다. 그래서 평가 세트에서 신호 감지가 잘 되는 것은 어느 정도 예상된 결과이며, 이 점을 결과와 함께 적습니다. 개발 세트(다른 모델이 신호 체계를 모르는 채로 쓴 대화)에서의 성능이 그 보정 역할을 합니다.
- 규칙 작성자가 평가 사례를 읽었다는 사실 자체는 없앨 수 없습니다 (stage2_engine_design.md 1장).
