# 흐름 판정 (작업 2-4) — v1

- 날짜: 2026-10-23
- 코드: `engine/src/main/kotlin/securityapp/engine/flow/FlowJudge.kt`(흐름 판정), `engine/RuleEngine.kt`(행위 감지 + 흐름 판정 연결)
- 상태: **개발 세트(합성 대화 33건)만으로 값을 정했습니다. 평가 세트는 이번에도 돌리지 않았습니다.**

## 1. 동작

방(대화방)마다 따로 판정합니다 (결정 13). 메시지 원문은 저장하지 않고, 방마다 아래만 남깁니다.

| 남기는 것 | 쓰는 곳 |
|---|---|
| 최근 상대 메시지 **8개**의 신호 | 조합 판정 (오래된 신호는 창 밖으로 밀려나며 약해짐) |
| 보낸 사람별 직전 글자 메시지의 신호 | 사진·파일만 있는 메시지가 앞 설명을 따름 (기준표 v2.1 1장) |
| 지금 단계 | 한 번 오른 단계는 내려가지 않음 (앱에서는 사용자가 "괜찮아요"로 내림) |
| 행위 감지의 방 맥락 (2-3) | R1·G2·G3·G4 |

"나"의 메시지는 단계를 바꾸지 않습니다. 앱에서는 받은 알림만 들어오므로, 평가도 같은 조건으로 돌아갑니다.

## 2. 규칙 v1

| 단계 | 조건 (최근 상대 메시지 8개 안) |
|---|---|
| 관찰 | 아래에 해당하지 않음. **신호 하나로는 관찰을 넘지 않음** |
| 주의 | 요구(D) 신호 + 다른 분류(P·G·R1) 신호. 단, 요구가 계좌 안내(D4)뿐이면 시간 압박(P3)·통화 회피(P4)만으로는 주의를 내지 않음 |
| 경고 | 주의 조건 + **돈 요구(D2·D3·D5)** + (D4를 뺀 서로 다른 신호 **3개 이상**, 또는 강한 신호 G3 금액 키우기·G4 붙잡기·D5 출금 조건·D6 비밀 유지) |
| 조합에서 뺌 | R2 친밀감 쌓기 (맥락 전용) |

판정 원칙(plan.md 4.2.3: 단독 경고 없음, 요구 + 다른 분류 조합, 메시지 수 기준 약화, R2 맥락 전용)은 그대로입니다. 바뀐 것은 계좌 안내(D4)를 다루는 방법뿐입니다 (결정 22).

경고가 오를 때는 이유 문장이 같이 나옵니다. 예: "돈 요구와 함께 여러 위험 신호가 이어졌습니다: 투자금 입금 요구, 수익 보장, …"

## 3. 값을 정한 방법 (개발 세트)

개발 세트에는 금전 지점 라벨이 없습니다. 그래서 사기 대화가 경고까지 가는지, 정상 대화가 주의·경고를 받는지로 비교했습니다.

| 창 크기 | 신호 수 기준 | D4 처리 | 사기 경고 / 주의만 (21건) | 정상 경고 / 주의 (12건) |
|---|---|---|---|---|
| 4 | 3 | 다른 신호와 같게 | 13 / 4 | 1 / 0 |
| 6 | 3 | 같게 | 14 / 4 | 1 / 1 |
| 8 | 2 | 같게 | 15 / 3 | 1 / 1 |
| 8 | 3 | 같게 | 15 / 3 | 1 / 1 |
| 8 | 4 | 같게 | 11 / 7 | 0 / 2 |
| 12·20 | 3 | 같게 | 15 / 3 | 1 / 1 |
| 6 | 3 | **v1** | 14 / 4 | 0 / 1 |
| **8** | **3** | **v1** | **15 / 3** | **0 / 1** |

- **창 8**: 6에서는 로맨스 대화 1건(claude_D07)이 경고를 놓쳤고, 8보다 키워도 달라지지 않아 작은 쪽을 골랐습니다.
- **신호 수 3**: 2와 결과가 같고, 4로 올리면 사기 경고가 15건에서 11건으로 줄어듭니다. 원칙 1(단독 경고 없음)에 더 가까운 3을 골랐습니다.
- **D4 처리 (결정 22)**: 정상 대화 2건이 계좌 안내 때문에 올라갔습니다.
  - 회비 걷기(gemini_D08)는 계좌 안내에 "오늘 내로 부탁드립니다"가 붙어 주의가 났습니다.
  - 진짜 지인의 투자 제안(gemini_D10)은 투자금 요구, 8% 보장, 법인 계좌가 모여 경고가 났습니다.
  - 고친 뒤 회비 걷기는 관찰, 지인 투자는 주의로 내려갔습니다. 8% 보장 약속이 있으니 주의는 맞는 결과로 봅니다.
  - 대가로 리딩방 1건(chatgpt_D01)의 경고가 상대 메시지 2개 늦어졌습니다. 그 사이에 송금은 없습니다.

**주의할 점**: 정상 12건 중 2건을 보고 정한 규칙입니다. 맞춰진 정도가 클 수 있으므로 2-5에서 AI-Hub Training 일반 대화(개발용)로 다시 확인하고, 평가 세트의 일반 대화 43건 결과를 그대로 보고합니다.

참고로, "나"가 보냈다고 말한 메시지를 낱말로 찾아 송금 시점을 대강 잡아 보면, 그런 메시지가 있는 사기 10건 중 5건에서 경고가 그보다 먼저 났습니다. 라벨이 아니라 낱말 검색으로 잡은 값이라 참고로만 적고, 송금 전 경고율은 평가 세트의 최종 라벨로만 계산합니다.

### 놓친 곳 (원인별)
- **행위 감지에서 놓침 (2-3 몫)**:
  - "최소 1천만원입니다"처럼 금액 조건만 말하는 투자 권유
  - "입금 후 입금증 보내주세요"
  - "정해진 금액만 보내면 돼요"
  - "보내 보세요"는 친구 사이에도 흔한 말이라 일부러 돈 요구로 보지 않았습니다.
- **앱 설치·카드 정보 위주의 흐름**: 공공기관 환급, 택배 통관은 D7(정보·앱 요구)과 D4만 이어지고 다른 분류가 없어 관찰·주의에 머뭅니다. 문자 한 통에서 시작하는 유형이라 기존 차단 도구가 맡는 영역이며, 이 프로젝트의 대상(대화가 이어지며 돈으로 넘어가는 흐름)에서는 벗어납니다. 규칙을 이쪽에 맞추지 않았습니다.
- **방이 나뉘는 흐름**: chatgpt_D01은 단체방의 맞장구(R1)와 1:1 방의 돈 요구가 서로 다른 방에 있습니다. 방 단위 판정이라 R1이 조합에 들어가지 못했습니다. 여러 방을 묶을지 판단하는 근거로 2-5에서 따로 기록합니다 (결정 13).

## 5. 테스트

64개 통과 (2-3의 49개 + 흐름 15개). 흐름 테스트에 쓴 대화는 모두 지어낸 것입니다. 다룬 내용:

- 신호 하나로는 경고하지 않음, 요구 + 다른 분류는 주의, 강한 신호
- 계좌 안내 처리 3가지
- R2 제외
- 창 밖으로 밀려남
- 단계 유지
- 친구 돈 빌리기, 수익 약속에서 증액까지 이어지는 대화
- "나"의 메시지
- 방 분리
- 사진이 앞 메시지를 따르는 경우
