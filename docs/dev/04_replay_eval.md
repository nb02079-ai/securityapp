# 재생 평가기 (작업 2-5)

- 날짜: 2026-10-24
- 코드: `eval/src/main/kotlin/securityapp/eval/`
- 상태: 개발 세트로만 돌렸습니다. **평가 세트(`data/eval/`)는 `--eval-set` 없이는 돌지 않게 막았습니다** (규칙을 `engine-v1`로 고정한 뒤 한 번만).

## 1. 하는 일

대화를 메시지 하나씩 엔진에 넣으며(재생) 세 방식을 같은 입력으로 비교합니다 (stage2_engine_design.md 5·6장).

| 방식 | 경고 조건 |
|---|---|
| 단어 기준선 | 상대 메시지에 **송금·입금·계좌·투자·수익** 중 하나라도 있으면 그 방에 경고. plan.md 7.2의 다섯 단어 그대로이며, 평가 뒤에 바꾸지 않음. 띄어쓰기 끼워 넣기는 엔진과 같은 정규화로 없앰 |
| 행위 단독 | 행위 감지가 신호(R2 제외)를 하나라도 찾으면 그 방에 경고 |
| 행위 + 흐름 | 엔진 그대로 (흐름 판정 v1) |

모든 방식은 **방 단위**로 판정하고, 사례는 방 중 하나라도 경고하면 경고로 봅니다 (결정 13). 처음 경고가 난 방도 기록합니다.

### "나"의 메시지
- **상대만 (기본)**: 앱은 받은 알림만 보므로, "나"의 메시지는 엔진에 넣지 않습니다.
- **나 포함**: 비교용으로 "나"의 메시지도 넣은 판입니다. 거절 뒤 붙잡기(G4) 같은 신호에 차이가 날 수 있습니다.
- **"나"가 정해지지 않은 일반 대화 (AI-Hub)**: 화자마다 한 번씩 "나"로 놓고 돌려, 한 번이라도 경고하면 오탐으로 셉니다 (결정 23). 대화에 참여한 누구든 앱을 쓸 수 있기 때문이고, 가장 엄한 기준입니다.

### 단체방 여부
앱에서는 알림이 단체방인지 알려 줍니다. 평가에서는 방 이름으로 정합니다.
- 단체방: `group…`, `단체…`, `오픈채팅…`
- 1:1: `dm…`, `sms`, `1:1…`, `문자`, `…채팅`, `…채널`
- AI-Hub 대화는 `speaker_type`(다자간 대화)으로 정합니다.

## 2. 지표 (설계 6장)

| 지표 | 계산 |
|---|---|
| 송금 전 경고율 (주) | 첫 송금 직전 메시지까지(포함) 경고한 사례 수 / 라벨 있는 사기 사례 수 |
| 조기 경고율 | 첫 금전 권유까지 |
| 결심 전 경고율 | min(첫 송금 의사 직전, 첫 송금 직전)까지 |
| 오탐 (주) | 일반 대화 중 경고가 한 번이라도 난 대화 수. 주의는 따로 셈 |
| 경고가 앞선 상대 메시지 수 | 첫 경고 뒤 첫 송금 직전 메시지까지 남은 상대 메시지 수 (송금 전에 경고한 사례의 중앙값) |
| ERDE5 · ERDE10 | 사기를 마감점 안에 잡으면 1 − 1/(1+e^(k−o)), 놓치면 1, 일반 대화에 경고하면 (사기 수 / 전체 수), 그 밖은 0. 이 비용을 모든 대화에 대해 평균. k는 첫 경고까지 넣은 상대 메시지 수. **o = 5, 10은 평가 전에 고정** (결정 23) |
| 신호 감지 정확도 | 최종 라벨이 있는 상대 메시지마다 신호별 맞음·잘못 붙음·놓침, 정밀도·재현율 ("나 포함" 판의 행위 감지 층) |

비율은 항상 건수와 같이 적습니다 (예: 7/10).

## 3. 결과 파일 (모두 UTF-8)

| 파일 | 내용 |
|---|---|
| `report.md` | 세 방식 비교표, 사례별 표, 경고·주의가 난 일반 대화 ID, 신호별 정확도 |
| `cases.csv` | 방식 × 보는 메시지 × 사기 사례마다 마감점, 첫 주의·경고, 경고 난 방, 성공 여부 |
| `normals.csv` | 방식 × 보는 메시지 × 일반 대화마다 가장 높은 단계 |
| `signals.csv` | 신호별 정확도 (`--labels`를 줬을 때) |

**대화 원문은 어떤 파일에도 쓰지 않습니다.** 사례 ID, 메시지 번호, 숫자, 묶음 이름만 씁니다 (AI-Hub 약관).

## 4. 실행

```
gradlew.bat :eval:run --args="--input data/dev/synthetic --input <AI-Hub replay_training 폴더> --out <저장소 밖 결과 폴더>"
```

- 상대 경로는 저장소 최상위 기준입니다.
- 인자에 한글을 넣지 않는 편이 안전합니다. 한글이 들어간 경로는 따옴표로 감쌉니다.
- 평가 세트를 돌릴 때만 아래처럼 실행합니다 (작업 2-6).
  `--input data/eval/scam --input <replay_validation> --points data/eval/scam/labels/final_points.csv --labels data/eval/scam/labels/final_messages.csv --eval-set`

AI-Hub Training 개발용 일반 대화의 결과는 아래 6장 절차로 사용자 PC에서 돌려 덧붙입니다.

## 6. AI-Hub Training 개발용 일반 대화 (사용자 PC)

1. Training 후보에서 묶음마다 고정 시드(20261020)로 뽑습니다. 개발용이라 직접 고르지 않고 뽑은 대화를 모두 씁니다 (`--select-all`).
   - 묶음 비율은 평가 세트 43건과 비슷하게 맞췄습니다: 금전 100, 연애·만남 50, 다자간 25, 주제만 25 → 200건
   ```
   py tools/aihub/extract_candidates.py sample --out <candidates_out> --split training --n-money 100 --n-romance 50 --n-group 25 --n-topic 25 --select-all
   py tools/aihub/extract_candidates.py export --out <candidates_out> --split training
   ```
2. `export`가 만든 `selected_ids_training.csv`(대화 내용 없음)를 `data/dev/aihub_training_ids.csv`로 저장소에 넣습니다.
3. 재생 평가기를 돌리고, `report.md`(ID와 숫자만)를 결과로 씁니다.
