# 새 평가 세트 재구성 (작업 4-3, 봉인)

engine-v1.1을 정직하게 평가하려면 **규칙 작성자(원래 세션)가 보지 않은 사기 대화**가 필요합니다. 그래서 다른 세션이 공개 사례를 재구성하고, 사용자가 저장소 밖에 봉인합니다 ([stage4_plan.md](../stage4_plan.md) 2장).

## 지켜야 할 것
- **이 프로젝트 밖의 새 대화**에서 진행합니다. 프로젝트 문서와 기억을 끈 상태여야 합니다. 웹 검색이 되는 모델을 씁니다 (Claude 새 대화, 또는 ChatGPT 검색).
- 결과 파일을 **원래 세션(규칙 작성 세션)에 올리지 않습니다.** 규칙을 `engine-v1.1`로 고정한 뒤에 올립니다.
- 저장소 밖 폴더에 보관하고, 아래 SHA-256 값만 커밋합니다.

## 지시문

```
한국 메신저 금융 사기(투자 리딩방, 로맨스 스캠, 지인·유명인 사칭 투자, 부업·미션 사기 등) 대화를 공개 자료를 바탕으로 재구성해 주세요. 사기 탐지 엔진의 "평가용" 데이터로 쓰입니다.

[출처 조건]
- 웹 검색으로 실제 사례를 다룬 국내 언론 기사, 판결문 보도, 수사기관·금융감독원 발표를 찾아 씁니다. 사례 하나에 출처 하나 이상, 주소와 날짜를 적습니다.
- 아래 출처는 이미 쓴 것이라 쓰지 않습니다:
  daum 20251220090142597(신동아 리딩방), dgmbc 617287, newspim 20240913000238, ilyo 466617, legaltimes 78553, fnnews 202610151326198661, daum 20251129063217635(뉴스1 부업)
- 서로 다른 사건 8~10건. 유형이 한쪽으로 쏠리지 않게 합니다.

[재구성 규칙]
- 사례마다 대화 10~30개 메시지. 출처가 전하는 흐름(접근 → 신뢰 → 유도 → 금전 요구, 그 뒤의 추가 요구)을 따릅니다.
- 메시지마다 근거를 표시합니다.
  - provenance: quote(출처 원문 인용) / described(출처가 서술한 행동을 메시지로 옮김) / connector(흐름을 잇기 위해 쓴 메시지)
- connector 메시지에는 돈 요구, 수익 약속, 비밀 요구 같은 위험한 내용을 넣지 않습니다.
- 출처에 없는 수법을 지어내지 않습니다. 모르는 부분은 짧은 connector로만 잇습니다.
- 링크·계좌·전화번호는 (링크), (계좌번호), (전화번호)로 가립니다. 실존 개인 이름은 쓰지 않습니다.
- 대화방: group / dm / sms 등으로 구분합니다. 피해자의 메시지는 sender "나", is_user true.

[출력]
1. CSV 하나: case,seq,room,sender,is_user,day,text,provenance,source_note
2. 사례 목록 표: case, 유형, 출처 제목, 주소, 날짜
```

## 봉인 (사용자 PC)
1. CSV와 사례 목록을 저장소 **밖** 폴더(예: `바탕화면\holdout_v2\`)에 저장합니다.
2. 해시를 구합니다.
   ```
   certutil -hashfile "%USERPROFILE%\Desktop\holdout_v2\holdout_v2.csv" SHA256
   ```
3. 나온 값, 날짜, 사례 수, 쓴 모델, **출처 주소 목록**을 원래 세션에 알려 주면 `docs/holdout_v2.md`에 기록해 커밋합니다. 대화 내용은 알려 주지 않습니다. 출처 주소는 원래 세션이 개발용 재구성(4-2)에서 그 출처를 피하는 데에만 쓰고, 기사를 열어 보지 않습니다.
4. `engine-v1.1` 태그 뒤에 파일을 올리면, 해시를 다시 맞춰 본 뒤 라벨링 → 평가로 진행합니다.
